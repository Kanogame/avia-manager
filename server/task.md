1. Инициализация и подключение к клиенту (IPC)
При запуске сервер должен принять в качестве аргументов свой уникальный ID (или сгенерировать его автоматически) и, возможно, путь/ID для подключения к клиенту.

Серверная сторона IPC:

Создать канал (ChannelCreate()) для приема команд от клиента.

Подключиться к клиентскому каналу (ConnectAttach()) для отправки данных о своем состоянии.

Реализовать отдельный поток (или неблокирующий цикл) для прослушивания канала команд с помощью MsgReceive().

2. Логика движения самолёта (Модель)
При старте сгенерировать случайные параметры в пределах заданной 3D-зоны обслуживания.

На каждом шаге (раз в секунду) вычислять новое положение, прибавляя к координатам вектор направления.

Обработка границ: При достижении края зоны корректно обрабатывать событие (например, менять вектор движения на противоположный или уходить на второй круг), чтобы самолёт не вылетал за пределы зоны видимости клиента.

При получении команды CHANGE_DIR пересчитывать текущий вектор движения так, чтобы он был направлен в новую целевую точку на краю зоны.

3. Главный цикл (1 Гц)
Использовать таймер (timer_create / SIGEV_PULSE для точного ритма в 1 секунду), чтобы с заданной периодичностью выполнять три действия:

Обновить координаты самолёта в памяти.
Сформировать структуру данных PlaneState (ID, x, y, z).
Отправить её клиенту через MsgSend.
Важно: Отправка данных не должна блокировать цикл движения. Если клиент временно недоступен, сервер должен продолжать полёт и накапливать или логировать ошибки отправки.

4. Обработка команд от клиента
Сервер должен постоянно ожидать команды от клиента через отдельный канал, созданный с помощью ChannelCreate().

При вызове MsgReceive() обрабатывать два типа входящих сообщений:

CMD_CHANGE_DIR: Получить новые координаты цели (X, Y), пересчитать вектор направления и продолжить полёт.

CMD_CRASH: Вывести в консоль сообщение "Plane [ID] crashed" и немедленно завершить процесс с кодом 0.
